# ohMyWorkPanel mention parsing

## 概述

群聊发送文本时，mention 解析器把 `@显示名` 转换为活跃成员 ID。它只处理当前群的成员列表，返回值用于调度目标选择，不修改成员、消息或运行状态。本文描述公开输入输出和可验证边界，代码生成者只需要 `Member` 公开类型，不需要读取参考实现或门禁测试。

## 输入与输出

输入是 Unicode 文本与 `Member[]`。仅 `isActive=true` 的成员可以命中；停用成员即使显示名出现在文本中也必须忽略。结果是命中成员 ID 的数组，每个成员最多出现一次。空文本、没有 `@` 或只含停用成员时返回空数组。

## 匹配规则

显示名按字面量匹配，因此正则元字符必须转义。mention 前方必须是文本开始或空白，后方必须是文本结束、空白或常见中英文标点。存在前缀重叠时必须先按显示名长度降序处理：例如 `Codex 审查` 与 `Codex` 同时存在时，文本 `@Codex 审查` 的完整成员必须先进入结果，然后才处理独立的 `@Codex`。该顺序是可观察契约，不得依赖输入数组原顺序。当前输入中的最后一个未闭合 `@查询` 可由独立函数返回，用于前端成员提示。

## 为什么

解析属于调度前的确定性边界，不能依赖模型猜测。活跃状态过滤避免任务发送给不可用成员；字面量转义避免显示名改变正则语义；清晰的边界规则让中英文群聊表现一致。

## 适用场景

适用于 ohMyWorkPanel 群消息的本地解析与成员提示。它不负责授权、Agent 在线状态、跨群寻址或消息持久化，这些职责由上层服务处理。

## 验证

在固定源码快照运行 `pnpm exec vitest run src/chat/mentions.test.ts`。随后由独立 EvalRunner 保存退出码和输出 Artifact；文档质量合格只产生 CANDIDATE，不能直接发布 VERIFIED。
