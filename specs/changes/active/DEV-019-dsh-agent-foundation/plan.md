# DSH 底座开发 Roadmap

状态：R0/R1 已通过并合入；R2 T103/T104 的真实 DocGen、独立检查与第二工作区修改复现已通过本地验收，PR #26 待审查。R3/R4 未开始；合入后执行 T200。实际证据见 evidence.md。

## 范围和维护方式

LangGraph 负责工作流编排，DSH 是外部第一版唯一的真实 Agent 运行框架。项目持有业务契约、工件、独立评测和确定性发布；不增加模型会话、工具调度或通用 Agent 运行器。Pi 依赖与固定项目执行器从公共运行路径退出，CodeAgent CLI 仅保留未来适配边界。

本文件维护阶段顺序；[tasks.md](tasks.md)维护执行勾选；[acceptance.md](acceptance.md)维护验收步骤；[evidence.md](evidence.md)追加实际结果；[开发状态](../../../../docs/DEVELOPMENT-STATUS.md)只记当前阶段和下一项。角色交付要求写入既有 `specs/06-agents/`，不再新建 roadmap、角色任务书或阶段报告。

## R0 → R1 的首个执行批次

1. 阅读最新工作区差异，保留本轮文档及其他未提交工作。需要隔离开发时创建 worktree 并执行 `npm run bootstrap:worktree` 至 `READY`，不能共享 `node_modules`；确保已确认文档随开发工作区一起可见。
2. 检查 Node 24、依赖、DSH SDK 和 Bubblewrap。先运行类型、Spec、架构及已有 DSH/角色契约测试，记录基线失败；不把基线失败静默略过。真实模型的网络和凭据单独检查，不输出秘密。
3. 选择可固定版本、无公司/NPU/外部服务依赖的 CPU 小模块。默认复用现成可信源码及参考测试，首个角色用 DocGen；模块需有正常、边界和错误行为，不能用恒定返回值夹具代表真实业务样例。选择结果及参考测试命令写入 evidence.md。
4. 沿组合根、配置、工作流节点、DSH SDK、结果校验和评测路径核对能力。取消、重试、恢复、会话隔离由谁负责写入 spec-delta；LangGraph 管业务恢复，DSH 管角色内部执行，节点不再建设第二套调度器。
5. 采用保守的旧数据处理方式：旧 Run 与审计保留可读，旧 Pi 快照禁止静默恢复成 DSH；拒绝时给出可操作原因，新任务创建新 DSH 快照。旧秘密配置不自动迁移，不删除用户数据；DSH 设置按实际协议重新验证。实现可逆的配置变更并测试旧数据读取。
6. 执行 R1：同步受影响正式规范，迁出 Pi 执行依赖与固定项目入口，完成 DSH 默认接线、配置/API/Console 联动和自动化回归；按验收结果回写勾选项。

环境缺少真实模型凭据时，继续能独立完成的代码和夹具验证，在 evidence.md 明确 live 阻塞；R2 不得标为通过。只有发现业务范围冲突、必须破坏现有数据或需要外部凭据等实际缺口才请求用户决策；模块、文件组织等常规实现选择在上述边界内直接推进。

## R1 需要覆盖的现有代码面

| 现有位置 | 开发目标 |
| --- | --- |
| `src/interfaces/runner/Composition.ts`、`src/application/services/AutomatedProjectWorkflow.ts` | 通用任务材料进入 LangGraph 节点；不再实例化 `OhMyWorkPanelWorkflowExecutor`，不得只改类名后保留固定路径/测试逻辑 |
| `src/infrastructure/agentAdapters/deepseek-harness/`、`src/infrastructure/langgraph/` | 复用 DSH SDK；节点仅准备授权材料、映射业务结果及关联事件；受限工作区、失败/超时/取消可验证 |
| `src/application/apps/ProviderOperationsApp.ts`、业务 ports、Provider 存储、server/Console | DSH 配置、验证、默认选择与 Run 快照一致；公共业务类型不依赖 Pi 或 DSH SDK 类型 |
| `src/infrastructure/agentAdapters/pi-agent/`、`package.json`、锁文件及调用方 | 删除 Pi 运行依赖；通用配置安全功能迁到独立位置继续复用；历史标识解析可保留，但不能加载 Pi SDK |
| 场景数据与评测入口 | 项目路径、源码版本和命令由显式场景提供；移除旧项目专属验收目录与命令，通用验收夹具只在测试中创建 |
| 当前 AgentProvider/业务 Schema 与公司 Adapter | 保留 CodeAgent CLI 未来交付相同业务结果的接口；默认启动不要求安装、认证或加载公司 CLI，不开发 DSH → CLI 嵌套运行 |

SDK 当前能力以仓库锁定版本和本地代码为准；需要升级时在实施差异中说明，不能按用户转述的公司 CLI 参数直接替换现有协议。

## 执行和验收规则

每个功能按“实现 → 相关检查 → 记录证据 → 勾选任务 → commit/push → 向 main 提 PR → 用户 review/合并”执行；合并后再推进下一功能。失败项修复后重验；未通过阶段不能被后续阶段的成功覆盖。R3 的角色逻辑可由不同负责人基于同一底座开发，本 roadmap 不预分人员、不自动派生多个 Agent。

每次修改同步受影响 Spec、实现、测试及操作说明；新目标条款随实现替换旧正式条款，保留历史证据的原始范围。角色权限与发布门禁不能因更换后端而放宽。DEV-014 草稿仅按职责选择性复用，不整体承接旧计划。

具体命令和证据要求以 acceptance.md 为准。新增真实范例/完整闭环入口必须在对应阶段实现并写入教程后执行；当前不把尚不存在的命令作为验收结果。
