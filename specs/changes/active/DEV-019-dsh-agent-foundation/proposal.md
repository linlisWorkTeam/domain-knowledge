# DEV-019 DSH 公共底座与角色开发范式

- 状态：架构方向已由用户确认，可执行 Roadmap 已落稿；实施 Spec 增量为 Draft；R0 已通过，R1 首批业务接线/夹具拆分与 DSH 关联检查已实现，完整 R1 尚未通过。
- 日期：2026-09-07。
- 负责人：公共底座负责人；具体人员在实施阶段分配。
- 目标里程碑：外部 DSH 底座与普通 CPU 角色范例，先于七角色业务开发和完整闭环。
- 关联需求：KF-SYS-001、004、006、010、011、017、019、021、022、025、031、041、042。

## 背景与目标

提案起点已有 LangGraph、DSH SDK、业务 Schema、Registry/CAS 和独立评测基础，公共角色逻辑集中在 `OhMyWorkPanelWorkflowExecutor`，前台模型配置绑定 Pi。R1 已拆出 `ProjectWorkflowStages` 与显式夹具，默认配置和通用启动迁到 DSH；R2 live 范例与独立工作区修改复现已通过本地验收，PR #26 待审查；后续为 R3/R4。

用户确认的目标是 LangGraph 编排、DSH 直接运行角色，系统持有业务结果校验与治理。复用 DSH 的会话、模型、工具及事件能力，不新建通用 Agent 运行框架。先完成底座与一个可复现范例，再由不同负责人开发七个角色。

Pi 退出目标底座，固定项目执行器退出公共入口；必要的上下文准备与工件交接保留为节点接线。保留 CodeAgent CLI 的未来适配位置，使其交付相同业务结果；第一版在外部用 DSH 完成，不等待公司平台或 CLI 环境。

## 本次文档交付与后续实施

首轮只更新架构、开发 SOP、教程、状态与本变更包。本轮已进入 R1 代码开发，实际范围和回归结果见 evidence.md；依赖、公开 API、业务 Schema 尚未切换。当前目标与已实现能力分别记录，原有夹具测试不算新底座的 live 证据。

开发按 [Roadmap](plan.md) 的 R0～R4 执行，每阶段有任务、验收和退出条件；完成 R4 即关闭 DEV-019，公司 CLI 另由 DEV-010 后置验收。常规实现选择在 R0 核实后直接推进，不再另起一轮整体架构规划。角色交付要求写入现有角色规范，阶段证据追加到 evidence.md，不新增任务书或报告。

后续实施交付 DSH 调用接线、角色配置与材料准备、业务结果校验、工件和日志关联、失败与取消处理，以及普通 CPU 小模块上的一个真实角色范例。范例附固定源码版本、公开接口、现成测试和可复现步骤。

## 范围与非目标

- 保留七角色职责、唯一 Registry、确定性 Gate、ArtifactRef、运行快照及数据边界。
- 本轮不编造 DSH 配置语法、CLI 参数或人员名单；文件拆分及配置细节在 R0/R1 按现有代码核实落实。
- 不要求底座阶段完成七个角色的全部业务能力；不把一个真实角色样例当成完整闭环。
- 不引入 DSH → CodeAgent CLI 嵌套调用，不开放任意拓扑编辑，不开展公司迁移或 NPU 性能验收。

## 与既有工作项的关系

编号 DEV-014 及其草稿引用的 DEV-015～018 已在其他 worktree 出现，因此本提案使用 DEV-019。它记录本轮确认的收敛方向，不承接旧 DFX 报告的全部范围。DEV-014 未提交改动须逐项核对是否符合本提案，不能直接视为已完成底座。

DEV-010 后置开展真实 CLI 协议对齐与验收；通用候选测试 Oracle 与 DEV-011 对齐，恢复和权限加固与 DEV-012 对齐，容量和 Redis 与 DEV-013 对齐。第一版完整闭环仍须兑现相关业务验收，后置公司适配不等于取消独立评测。

## 主要风险

DSH 能运行角色，不代表其响应已符合业务 Schema 或通过真实性验证。取消、会话隔离、权限和恢复需分别证明。Pi 配置与历史 Run、固定场景入口和旧验收证据的处置须在实施前明确；本提案不授权静默替换旧 Run 的执行后端。
