# LangGraph 多 Agent 框架阶段性测评

## 结论

当前可以汇报为：**框架机制已通过确定性验收，真实 Agent 效果尚未评测，生产可用性尚未评测。**

这意味着 LangGraph 选型已被证明能够承载本项目当前的固定七 Agent 拓扑、并发分支、迭代、Checkpoint 恢复、取消和确定性 Gate；但在公司 CodeAgent 尚未接入、真实任务集尚未建立之前，不能声称知识质量、代码质量、成本、吞吐量或生产稳定性已经达标。

## 测评边界

```text
本阶段可以证明                         本阶段不能证明
──────────────────────────────────    ──────────────────────────────
七个 Agent 都在图中并实际被调度         真实模型生成内容是否足够好
输入输出契约会 fail closed              公司 CodeAgent CLI 是否稳定
Run 配置在启动时被冻结                  并发容量、耗时、成本是否达标
并行、循环、取消和 Checkpoint 可工作     敌对代码是否能被安全执行
基础设施失败不会交给 ReviewAgent         真实业务知识是否可直接发布
只有确定性 PASS 可以发布
```

因此，本报告评价的是“框架能不能正确承载 Agent”，不是“Agent 本身聪不聪明”。

## 自动化基线

从仓库根目录执行：

```bash
npm run evaluate:framework
```

命令输出一份 JSON 报告，任一关键检查失败时退出码为非零。它不调用公网模型、不要求 CodeAgent 登录，也不写入现有 HTTP API。

## 汇报建议

建议把当前状态分成三句话：

1. **选型合理性**：LangGraph 已覆盖固定拓扑、并行、循环、Checkpoint 和恢复需求，且被自动化测试锁定；当前没有证据表明需要更换编排框架。
2. **框架可用性**：使用确定性 Fixture 时，七个 Agent 的工作关系、契约、评测和发布闭环能够完整运行，框架层验收通过。
3. **效果待验证项**：真实 Agent 的生成效果以及公司环境的性能、成本和稳定性仍需在 CodeAgent Adapter 接入后单独测量，不能用 Fixture 结果代替。

## 下一阶段指标

接入公司 CodeAgent 后，保持本报告的框架基线不变，再增加真实效果指标：

- 任务成功率：完整跑到确定性 Gate 的 Run 占比；
- 一次通过率：无需 `ITERATE` 即达到 PASS 的比例；
- 人工采纳率：生成文档或修订被审核人接受的比例；
- 契约失败率：Provider 原始输出无法规范化为 `AgentResult` 的比例；
- 恢复成功率：超时或进程失败后从 Checkpoint 恢复成功的比例；
- 时延与资源：各节点 P50/P95 时延、CLI 进程峰值内存和并发上限；
- 成本代理：公司侧可取得的调用量、token 或配额消耗指标。

这些指标不要求修改现有前台或 HTTP API。若以后需要在 Console 展示框架测评或真实 Agent 指标，应由前台/API 负责人先定义新增只读接口，本后台分支不预先扩展响应结构。
