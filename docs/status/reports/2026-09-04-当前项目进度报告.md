## 二、第一版已形成的闭环

当前实现已经具备以下单项目 Preview 闭环：

1. 注册来源并固定真实 Git commit、Run Policy、Provider、模型、提示词、工具权限和 Schema 摘要；
2. Orchestrator、DocWorker、DocGen、TestGen、Code、Check、Review 七个固定角色按 LangGraph 拓扑运行；
3. 候选知识先经过确定性 Quality Gate，不合格时跳过 Code 并把 weak points 反馈给下一轮 DocGen；
4. Code 只根据候选知识和公开接口在 fresh 工作区生成实现，不能读取参考实现、门禁测试或上一轮代码；
5. 独立 EvalRunner 执行受控构建和测试，产出不可变 Artifact 与 EvaluationReport；
6. Review 只负责证据归因和 Correction，最终由确定性 Gate 决定 `PASS / ITERATE / ROLLBACK / STOPPED`；
7. `PASS` 后以原子事务写入 `VERIFIED`、publication receipt 和审计事件；人工修订必须创建新版本和新 Run；
8. Console 可查看和治理事项、批次、知识、工作流图、评测、来源及 Agent 设置，并使用真实服务端投影、SSE 和轮询降级。

确定性 fixture 已验证“失败 → 归因 → 知识修订 → fresh 代码生成 → 独立评测 → 发布”的完整机械闭环。Pi SDK 和 DeepSeek Harness 已有执行路径证据，但外部模型效果、容量和长期稳定性不能由 fixture 推导。
