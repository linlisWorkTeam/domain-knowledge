# 框架测评与验收方案

> 本文只测“LangGraph 整体框架是否可靠”，不提前测尚未定型的 Agent 业务能力。

## 1. 为什么要分开测

当前最容易混淆的是两种效果：

- **框架效果**：节点有没有都运行、路由是否正确、并行是否正确汇聚、失败后能否恢复、Adapter 是否可替换；
- **Agent 效果**：知识是否准确、测试是否有辨别力、代码是否符合源码行为、Review 是否能找出真正问题。

V1 先验收前者。否则 Agent Prompt 尚未确定时，端到端质量波动会掩盖真正的编排 Bug。

## 2. 测评金字塔

| 层级 | 验证效果 | 实现难度 | V1 做法 |
|---|---|---:|---|
| 静态拓扑检查 | 证明所有节点、边、终态和循环都存在，防止节点被擅自删掉 | 低 | 读取图描述并与固定清单比对 |
| 节点契约单测 | 证明 State 输入输出、ArtifactRef 和错误类型符合协议 | 低 | Fake 输入 + Schema 校验 |
| 路由/门禁表驱动测试 | 证明 pass、iterate、rollback、stopped、failed 不被 LLM 随意改变 | 中 | 构造结构化 Eval/Check/Review 报告 |
| 全图 smoke | 证明 7 类 Agent 和确定性组件能连起来跑完 | 中 | 全部使用 Fake Runner |
| 并行与 join 测试 | 证明 Send 真 fan-out，join 等待全部分支，失败能传播 | 中 | `workerCount >= 2`，记录开始/完成事件 |
| Checkpoint 重启测试 | 证明进程重启后已完成节点不重跑，从正确边界继续 | 中高 | SQLite + 两阶段测试进程 |
| 故障注入测试 | 证明超时、异常、损坏 Artifact、认证失败都进入预期终态 | 中 | 可编程 Fake Runner |
| 物理隔离测试 | 证明 CodeAgent 真的看不到 source/tests，而非仅靠 Prompt | 高 | 临时工作区 + 违规读写探针 |
| Adapter 替换测试 | 证明 Fake→Codex 只改注册表或配置，不修改图 | 中 | 同一 contract suite 跑两个 Runner |
| 真实 Codex 代表节点 | 证明登录额度、会话、产物落盘和恢复接缝可用 | 高且有外部波动 | 只选 1 个代表节点，单独标记 integration |

## 3. 必测场景

### F01：完整 happy path

Fake Agent 全部成功，Eval pass，Check/Review 无 blocking issue。断言：

- `OrchestratorAgent`、`DocGenAgent`、`TestGenAgent`、`CodeAgent`、`CheckAgent`、`ReviewAgent` 都有事件记录；
- 设置 `workerCount = 2` 时，两个 `DocWorkerAgent` 实例都有事件记录；
- 候选知识、Oracle 校验、Eval、Gate、知识发布都执行；
- 最终状态为 `COMPLETED`。

### F02：业务失败后迭代

第 1 轮 Eval fail，第 2 轮 pass。断言 Review 在两轮都运行，Gate 第 1 轮返回 iterate，图再次经过 Orchestrator 和 DocGen，最终完成。

### F03：Review 降级

Eval pass，但 Review 给出 blocking issue。断言 Gate 返回 iterate，而不是 pass。

### F04：禁止 Review 升级失败

Eval fail，而 Review 错误地建议 pass。断言确定性 Gate 仍不得发布。

### F05：基础设施失败

Evaluator 返回 infra error。断言直接进入 `FAILED`，不生成伪业务结论，也不运行 Review。

### F06：critical regression 回滚

存在 historical best，当前轮出现确定性 `criticalRegression`。断言 Gate 返回 rollback，恢复的 Artifact 哈希与 historical best 一致，再进入后续调度。

### F07：达到迭代上限

连续业务失败直到 `iteration == maxIterations`。断言终态为 `STOPPED/LOW_CONFIDENCE`，不再调用 Agent，保留失败证据和 historical best。

### F08：并行 fan-out 与 join

设置不同完成延迟的多个 Fake DocWorker。断言：

- 存在时间重叠，证明不是伪并行；
- DocGen 在全部必需 worker 完成后才汇总；
- 任一必需 worker 失败时，join 不产生不完整成功结果；
- `workerCount = 0` 时仍走明确的 DocGen 直达边。

### F09：Checkpoint 恢复

运行到 CodeAgent 提交后主动终止进程，再以相同 `runId/thread_id` 恢复。断言前序节点调用次数不增加，从 checkpoint 后继续。

### F10：节点中途崩溃

分别覆盖三种情况：有效 committed Artifact、仅有可恢复 thread、两者都没有。断言依次执行“复用 Artifact、恢复 thread、新 attempt”的策略。

### F11：Artifact 完整性

篡改已提交文件。断言 SHA-256 校验失败，不将损坏产物注入后续节点，并产生明确错误。

### F12：工作区隔离

让每个 Fake Agent 主动探测禁读路径和禁写路径。断言所有越权均失败，尤其 `CodeAgent` 无法读取 source 和 tests，`TestGenAgent` 无法读取 knowledge。

### F13：Runner 可替换性

同一图先用 Fake DocGen，再只通过注册表换为 Codex DocGen。断言图节点、边、GraphState Schema 和 Gate 代码均无 diff。

### F14：认证与额度失败

模拟没有 Codex 登录或额度不可用。断言明确失败并可诊断，不静默切换 API key、模型或其他 Runner。

### F15：取消与恢复边界

通过 Service API/CLI 取消 run。断言状态可查询、已提交 Artifact 保留、后续节点不再启动；只有显式支持的状态才能 resume。

## 4. 可编程 Fake Runner

Fake 不应只是固定返回字符串。它至少支持：

```typescript
interface FakeAgentBehavior {
  delayMs?: number;
  result?: "success" | "business-failure" | "infra-error";
  artifacts?: FakeArtifactSpec[];
  failAt?: "prepare" | "execute" | "commit";
  tryForbiddenRead?: string;
  tryForbiddenWrite?: string;
}
```

每次调用都记录 `runId`、node、iteration、attempt、开始时间、完成时间、输入 ArtifactRef 和输出 ArtifactRef。这样才能用确定性证据验证顺序、并行和是否重复执行。

## 5. 自动验收指标

| 指标 | V1 验收要求 |
|---|---|
| 节点清单完整率 | 7/7 Agent 类型存在；必需的确定性环节全部存在 |
| 必测场景通过率 | F01–F15 全部通过；真实 Codex 场景可单独标记为需登录的 integration |
| 非法发布次数 | 0；Eval fail、blocking review、损坏 Artifact 均不得发布 |
| checkpoint 前序重复执行 | 0 次，除非该节点没有完成 commit |
| Artifact 可验证率 | 100% 的跨节点主要产物有 SHA-256 和生产者信息 |
| 越权访问成功次数 | 0 |
| Fake→真实 Runner 所需图变更 | 0 |
| 路由可复现性 | 相同结构化输入始终得到相同 Gate 结果 |

时间、Token 和成本应记录，但 V1 不设置未经实测的硬阈值。先建立基线，再决定预算。

## 6. 真实 Agent 测评何时加入

框架通过上述验收后，再逐节点增加业务效果评测：

- DocGen：事实覆盖率、引用溯源、矛盾率；
- TestGen：Oracle 正确率、覆盖率、mutation score；
- CodeAgent：held-out test 通过率和禁止信息泄露；
- Check/Review：缺陷召回率、误报率、blocking 严重度一致性；
- 知识飞轮：跨轮提升、回归率、达到稳定状态所需迭代数。

这些指标需要固定数据集和人工标注基线，目前只预留 Evaluator 接口，不阻塞框架骨架。

## 7. 最终判断标准

框架“有效”不等于某次 Demo 看起来不错，而是同时满足：

1. 完整拓扑在 Fake Agent 下可重复运行；
2. 图行为在成功、失败、恢复、并行和循环场景下符合规则；
3. Fake 替换为真实 Codex 不改变图；
4. 新增或替换 Agent 不重写 State、Artifact、Gate 或运行时；
5. 所有节点都能被测试证明确实存在且被实际执行过。
