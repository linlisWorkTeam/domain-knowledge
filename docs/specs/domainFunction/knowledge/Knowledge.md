# 知识实体与正文差异设计

代码位置：[src/domain/Domain.ts](../../../../src/domain/Domain.ts)、[src/domain/knowledge/MarkdownDiff.ts](../../../../src/domain/knowledge/MarkdownDiff.ts)。


## 实体与不变量

ArtifactRef 以 sha256、大小和媒体类型描述正文。KnowledgeVersion 保存版本身份、moduleId、父版本、正文引用、来源与状态；同模块同正文可去重，修订创建新版本。Run 保存业务状态和当前轮次；非法状态迁移由 Domain 拒绝。

CANDIDATE 是未发布版本；质量评分 ACCEPTED 只表示可进入后续生成和评测。VERIFIED 必须关联有效 Gate 与唯一发布回执；被后继发布替代的版本保留 SUPERSEDED 历史。LOW_CONFIDENCE 保留停止证据。回滚状态仅为迁移兼容，当前不自动选择历史最优并回滚。

生命周期规则归属 [workflow](../workflow/Workflow.md)，Gate 判定归属 [evaluation](../evaluation/Evaluation.md)，事实提取和关联校验归属 [association](../association/Association.md)。

## 查询与差异

MarkdownDiff 对正文做结构化行差异，给出段落与范围校验信息；Application QueryService 与内容治理服务提供血缘、关系、评测、来源和反馈投影。查询不改变发布状态。HTTP 管理目录可读取多个状态，消费端若只接受已发布知识必须明确过滤和验证正文。

## 文档描述、索引与渐进加载（已确认，待实现）

[DocGen IO-22](../agents/docGenAgent/DocGenAgent.md) 已确认：DocGen 生成单份知识文档的标题、摘要和关键词；框架负责校验、写入 YAML 头并建立支持渐进式加载的索引，不增加 Agent 身份。读取方先按索引描述选择所需知识，再加载相应正文；单次飞轮仍只以 IO-18 规定的一份文档为修订对象。

索引条目应对应明确的文档版本和正文引用，修订后同步更新描述及索引，避免描述与正文错配。发布及读取权限沿用既有规则，索引不能使未授权的源码、测试或其他运行材料进入 CodeAgent。索引属于文档的派生数据，不替代知识版本、评测记录和发布判定；具体格式、存储、更新与渐进加载接口待实现及验收。

## 持久化交接

Domain 产生状态、事件、工件描述和 Gate 判定；Application 协调写入，SQLite 实现事务、幂等和约束。领域代码不直接更新数据库。内容评分的现有实现位于 Application QualityPolicy，所属设计在 Application 文档中说明。

| 编号 | 议题 | 状态 | 记录 |
| --- | --- | --- | --- |
| IO-19 | 单文档飞轮的过程资料保留与清理 | 已确认（待实现） | 2026-09-10 用户确认：运行期间保留过程资料；结束时整理验收记录或精简治理清单；质量达标后保留最终文档并清理中间产物，需要人工治理时暂存相关证据。保存范围与人工默认查看范围分开，避免要求人工遍历所有轮次。用户随后明确文档达标后立即清理中间资料，不设置一周或其他额外保留期；先确保最终文档及验收记录保存成功。此明确决定取代此前清理时机待确认的描述。 |

本规则围绕 [DocGen IO-18](../agents/docGenAgent/DocGenAgent.md) 的单份知识文档生效。运行期间保存候选文档、生成代码、评测及修订证据，便于各轮比较和问题定位；不承诺所有过程资料永久保存。

| 结束状态 | 必须保留的成果与记录 | 过程资料处理 |
| --- | --- | --- |
| 文档质量达标 | 最终知识文档、对应源码版本、测试集引用、评测结果和采用原因组成的简短验收记录；若替换已在使用的文档，额外保留被替换的上一版以便回退 | 最终文档及验收记录保存成功后，立即清理中间候选文档、生成代码及编译产物，不设置额外保留期 |
| 需要人工治理 | 待治理文档、问题段落、问题说明与建议、对应失败用例或代码差异，必要时附上一版对比 | 后台暂存解决问题所需的相关版本和完整证据，人工默认只看精简治理清单，需要时展开证据 |
| 人工治理完成 | 达标后保留最终文档、验收记录及治理结论；未解决的问题继续保留对应证据 | 治理后达标且最终文档、验收记录及治理结论保存成功，立即清理可清理的过程材料；未解决问题的证据继续暂存 |

清理生成代码后仍可追溯验收结论，但不能完整复查当时生成的代码；该取舍已随本规则接受。共享测试集按既定源码不变则复用的规则保存，不作为每轮临时副本删除。清理实现需区分必须保留的验收、发布与治理记录和可清理工件，避免删除其他运行或仍保留记录所需的共享资料；现有正文引用和血缘查询如何表示已清理材料，须在实现前细化。

Review 提炼问题及有价值的历史尝试，例如某轮修复问题 A 却引入问题 B，避免人工重复尝试；Application 组织治理材料及其证据引用。精简展示不等于提前删除后台证据，Review 不直接清理工件或作出发布判定。

本节是目标保留政策，不代表自动清理或治理界面已经实现。本次仅记录设计，不执行实际删除。达标后立即清理的时机已确定，治理清单机器契约、证据访问方式和清理执行机制待实现。达标自动结束并交付、最大轮次未达标或预算耗尽转人工治理，沿用 [Evaluation IO-20](../evaluation/Evaluation.md) 及既有总体规则。保留历史最佳和关键回归回滚已有目标要求，评分可比性与回退实现细节仍需落实，不重新确认已有原则。
