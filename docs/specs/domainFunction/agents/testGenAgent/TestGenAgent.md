## 已确认的业务输入

主要业务输入为源代码；知识卡片不进入 TestGen 的输入材料或读取范围。源码输入方向与当前实现一致，本次确认不代表具体文件白名单及全部输入字段已经验收。独立接口材料、项目配置和测试策略如何提供仍需细化。

此前提出的“根据知识卡片生成测试”方案不再适用；已有测试按 IO-13 根据输入源代码复用。输出范围与执行分工已按 IO-11 确认，具体契约、预期结果校验与执行器接线仍待落实。

## 目标输出（已确认，待实现）

| 输出 | 约定 |
| --- | --- |
| 测试源码 | 可交给执行器编译、运行的 C/C++ 测试文件 |
| 用例清单 | 每个用例的测试目标、输入、预期结果及源码依据 |

TestGen 生成测试材料，后续执行器负责运行；生成成功不等于测试执行成功或用例已经可信。文件路径、清单机器字段、测试框架及构建接线待细化；预期结果按 IO-12 暂定流程校验，已有用例按 IO-13 复用。

## 已有测试用例的复用（已确认，待落实）

没有已有用例时，TestGen 根据输入源代码生成测试；已有用例且输入源代码未变化时，继续使用同一套测试，不重新生成。知识卡片修订或 CodeAgent 重新生成代码时，测试用例保持不变，以便比较各轮结果。

本轮讨论中提出的“测试要求或构建环境变化也可能触发重新生成”不作为自动触发规则。执行器仍可重新编译、运行既有测试，执行结果或环境故障不等于用例需要重新生成。未通过首次校验的候选按 IO-21 兜底修复，不把无效候选直接视为已校验测试集。

具体如何识别源代码变化，以及变化后更新全部还是受影响用例，尚待落实；不能把无关提交、配置或知识卡片变化直接当作源代码变化。

## 测试校验流程（暂时保留，待实现）

TestGen 根据源代码生成测试源码及预期结果，执行器先将这套测试用于原始源码。测试通过后固定测试集，再用同一套测试评测 CodeAgent 的生成代码。若测试无法编译、运行失败或断言不符，先排查测试、接口调用及环境原因；未经校验的失败不能直接转成知识修订依据。

源代码默认正确，本步骤利用其行为校准生成的测试，不重新判断源代码业务正确性。通过只说明这些测试与参考实现相容，不证明覆盖完整或测试没有遗漏；失败兜底遵守 IO-21，具体错误分类、修复材料契约和重试上限配置仍待实现时细化。

| 编号 | 议题 | 状态 | 记录 |
| --- | --- | --- | --- |
| IO-21 | TestGen 首次候选校验失败后的处理 | 已确认（异常兜底） | 2026-09-10 用户同意：新生成的测试在原始源码上校验失败时，将失败信息交回 TestGen，限定次数修复并重新校验；仍失败再转人工处理。用户强调只作为兜底，不将修复作为每次生成后的必经步骤。 |

正常流程为生成候选测试、在原始源码上校验、通过后固定测试集；仅校验失败时进入修复分支。执行器产生失败证据，Application 将候选测试、相关源码及失败信息按权限提供给 TestGen；修复结果仍须由执行器校验，通过后才能进入门禁集。基础设施或环境故障先区分原因，不直接作为修改测试的依据。

该兜底仅针对首次生成、尚未校验通过的候选，不改变 IO-13 的源码不变则已有测试不变规则。不得将测试候选失败直接归因为知识文档错误。本次不指定失败发生率，也不以模型能力代替执行校验；具体修复次数与配置字段属于后续实现细节，当前尚未实现此分支。

## 本轮实施约定（2026-09-10）

IO-11 输出采用 files（path/content）与 cases（caseId、testPath、target、input、expected、sourceEvidence）。仅允许配置指定的 C/C++ 测试路径，清单必须引用已生成文件和授权源码。框架分别保存测试文件集合与清单。IO-12 使用项目配置的编译/运行命令在原始源码上校验，再把同一测试文件覆盖到生成实现的评测目录。IO-13 按源码路径及内容摘要构造复用键，不含知识、提示词、构建配置或无关 Git 提交；已通过的集合保持不可变。IO-21 默认最多一次修复（可配置 0～3），失败证据显式交回 TestGen；基础设施失败不触发模型修复，耗尽返回人工处理结果，不能进入代码测评。
