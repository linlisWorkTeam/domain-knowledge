## 当前输入输出

IO-11～13、21 的约定已接入当前流程，IO-12 仍为暂时保留的产品规则。TestGen 只接收源码快照、接口、C/C++ 语言与测试编写策略，不读取知识卡片。allowedTestPaths 限定输出路径；修复时额外提供 previousCandidateRef 和 validationFailureRef，二者必须同时出现。

输出 `files`（path、content）与 `cases`（caseId、testPath、target、input、expected、sourceEvidence）。路径必须是授权的规范 C/C++ 文件，不能覆盖输入源码或接口；用例必须关联实际生成文件，源码依据只能引用授权路径。框架将测试文件集合与清单分别保存为 candidateSetRef 和 caseManifestRef。

## 原始源码校验与复用

执行器在固定提交的原始源码副本覆盖测试文件，通过配置的 referenceCommands 编译、运行。通过后固定测试集，再把同一集合与 Code 生成文件一起放入独立副本，运行 finalCommands。测试清单按下方 AC-AGENT-103 的独立 runner 协议逐项执行；退出码与汇总计数不能替代清单完成证据。

源码身份由模块标识、输入源码/接口路径及内容摘要确定；无关 Git 提交、知识、模型提示词和编写配置不进入身份。SQLite 保存不可变的首个通过集合，后续 Run 和文档迭代不重新调用模型生成测试，但会在当前环境重新编译运行。测试路径配置变化也不重写已有集合；如果新环境不能运行固定测试，转人工处理。源码变化后创建该源码身份对应的新集合，当前按整个选定模块更新。

## 首次失败修复

候选编译失败、运行失败或断言不符时，框架将当前候选及失败证据交回 TestGen。`agentConfiguration.maxTestRepairs` 默认 1，范围 0～3；每次修复使用独立执行键并再次校验。正常通过不进入修复。

准备阶段失败、超时等基础设施故障不触发模型修复。修复耗尽或固定测试复用失败返回 testValidationRequired，沿现有 STOPPED 路由等待人工处理，不将候选测试失败交给 Review 修订知识。运行中断可复用已提交候选和校验记录；并发 Run 争用同源测试时重验最终固定的集合。

## 验证与限制

真实 g++ 测试覆盖首次失败后修复、编译失败修复、耗尽停止、环境故障不修复、跨 Run 复用、配置变更复用及恢复；完整流程覆盖同一测试集测评两轮生成代码。C++ 的受控材料通过不证明真实业务测试覆盖完整，也不证明原始源码业务正确性。具体证据见 [Status](../../../../Status.md)。

## 本轮缺口修复验收

参考校验和重建评测必须把生成测试绑定到项目配置的编译与执行命令，保留项目参数；框架追加独立 runner 执行固定清单。修复输入必须包含上一候选的完整文件和用例正文。具体契约及验收如下。

## 强制约束与可执行验收（2026-09-11）

以下是本轮必须实现的契约，不因现有测试通过而视为已完成。

| 验收编号 | 强制规则 | 必须验证的场景 | 验收入口 |
| --- | --- | --- | --- |
| AC-AGENT-101 | cases 只关联可执行测试翻译单元；辅助头文件不需要虚构 case；每个测试翻译单元必须有关联 case | .cpp + .h 正常编译执行；仅头文件、把头文件声明成入口、未关联翻译单元在模型输出校验处失败 | `node --test tests/integration/TestEntryContract.test.ts` |
| AC-AGENT-102 | 执行器依据项目提供的受信原生编译命令绑定生成测试，不自行丢弃宏、头文件目录、链接参数和运行限制 | 必需 -D、-I、链接参数保留；缺少编译/运行绑定转人工，不尝试修改测试补救配置问题 | `node --test tests/integration/TestBuildBinding.test.ts` |
| AC-AGENT-103 | 固定清单每个 caseId 对应唯一 entryPoint；由框架生成 main 并调用所有入口，框架记录逐项结果；Gate 只接受完整匹配的执行证据 | 少一个用例、重复/未知记录、跳过、提前 exit(0)、只打印成功计数都不能通过；完整清单通过；修复及复用仍绑定同一清单 | `node --test tests/integration/TestCaseExecution.test.ts` |

AC-AGENT-103 的 C/C++ 测试协议：每个 case 增加合法 C 标识符 `entryPoint`；生成测试定义 `int entryPoint(void)`，返回 0 表示通过，非 0 表示失败，禁止生成 main。Infrastructure 生成独立 runner，调用入口后发出带本次执行随机标识的逐项记录。入口调用前退出、缺记录、重复记录、未知记录、失败记录均不能 PASS；模型自行打印的 TAP/总计不构成该清单的执行证明。此协议保证调度和完成性，不证明测试断言的业务质量。

受信原生构建绑定限定为可解析的 gcc/g++ 编译链接命令及其 binary 执行命令；编译参数须显式包含生成测试翻译单元、-o 目标及匹配的运行命令。框架在编译命令中追加自己的 runner，保留其他项目参数和独立检查命令。无法证明绑定关系的脚本、缺失入口或不支持的布局须显式报告配置问题并转人工，不退回成功计数策略。Code 仍不能获得这些构建参数或测试材料。

逐项证据属于本次评测工件，绑定源码提交、测试源码摘要、清单摘要和重建文件摘要；项目附加测试及重复运行不得抵消清单缺项。旧测试协议缓存不能作为新协议的成功证据；保持源码不变不自动重新生成的既有原则，无法复用时转人工。

## PR #46 独立复审补充（2026-09-11）

此前 nonce/stdout 方案不构成可信完成证据，AC-AGENT-103 重新打开。威胁模型包含生成的原生代码读取 runner、伪造任意输出、直接 exit(0)、尝试篡改文件或监督进程；不把隐藏文件名或随机字符串当安全边界。测试断言本身是否充分仍由业务质量验收负责。

- AC-AGENT-103-R1：每个清单入口由外部监督器独立启动，观察实际入口到达和函数返回值；子进程 stdout/stderr 仅作日志。结果经子进程无法写入的独立通道交给评测器。提前退出、崩溃、超时、监督失效均失败；一个入口失败不能掩盖或阻止其他入口被调度。
- 当前监督执行支持 Linux x86_64 的 ptrace，拒绝子进程派生进程、写文件、修改其他进程及切换程序等越权系统调用；不支持的平台、工具或命令布局明确失败，不能退回 stdout 计数。此限制是测试执行配置，不等于完整部署沙箱或任意项目运行兼容性。各用例独立进程，不依赖跨用例全局可变状态。依据：[ptrace 手册](https://man7.org/linux/man-pages/man2/ptrace.2.html)。
- 必须验收公开复现：第一个入口读 runner、打印三个 PASS 然后退出，后两个入口返回失败；总结果不得通过，且后两个入口仍由监督器启动。还须覆盖直接退出、普通返回、信号、超时、结果通道伪造和监督器不可用。入口符号缺失不能通过。
- AC-AGENT-102-R1：编译输入、输出和 binary 参数分别相对于各自 cwd 规范化为仓库相对路径；支持根目录内的 `.` 和 `..`，拒绝逃出根目录，原始参数不改写。验收 `cwd=build` 的 `../tests/generated.cpp -o test-bin` 配合相同 cwd 或根目录运行，以及越界/符号链接拒绝。

验收入口沿用 `tests/integration/TestCaseExecution.test.ts`、`tests/integration/TestBuildBinding.test.ts`，另增加外部监督器集成验收。旧逐项协议升级并拒绝作为新协议的成功缓存。
