# 决策记录与待定项

> 用途：防止“框架骨架已确认”被误解为“所有 Agent 细节已定稿”。

## 1. 已确认决策

| 主题 | 当前决策 |
|---|---|
| 顶层编排 | LangGraph 是唯一顶层编排器 |
| 语言 | TypeScript |
| 节点 | 7 类 Agent 全部保留，不擅自删除、合并或绕过 |
| 未实现节点 | 使用 Fake Runner 占位，但仍进入图、状态、日志和测试 |
| Orchestrator | V1 使用确定性代码 |
| Gate | 确定性代码；`pass / iterate / rollback / stopped` |
| 首个真实后端 | Codex，复用现有登录额度 |
| 降级 | 登录/额度失败时显式失败，不静默换模型或 API |
| Agent 接入 | `AgentRunner` Adapter，内部实现不能改顶层图 |
| DocGen 会话 | 同一 run 的修订默认复用自己的 thread，可配置 |
| Review 会话 | 每轮默认 fresh thread，可配置 |
| State | 只放小状态与 ArtifactRef，不放大文本 |
| Artifact | `.agent-runs/{runId}` 本地落盘、SHA-256、completion marker |
| Checkpoint | 默认 SQLite，测试 InMemory；`runId = thread_id` |
| 恢复范围 | V1 只保证单实例重启恢复 |
| 权限 | 节点级 allowlist，未授权即失败，默认不提权 |
| 并行 | Fake smoke 真并行；Codex 默认顺序，可配置最大 2 |
| DocWorker | 节点和 Send 路径保留；默认 workerCount=0，测试必须 >1 |
| Eval | `Evaluator` 接口；Fake + 可配置 Command 实现 |
| Review | 所有有效业务 Eval 报告均经过 Review；infra error 除外 |
| maxIterations | 默认 5，可配置 |
| 入口 | TypeScript Service API + CLI，HTTP 后续复用 Service 层 |
| 当前测评目标 | 测框架正确性；真实 Agent 质量后续单独测 |

## 2. 暂定决策

以下内容已有 V1 默认值，但必须通过配置或接口保留调整空间：

- DocGen 和 Review 的 Codex thread 复用策略；
- Codex 并发上限初始值 2；
- `maxIterations = 5`；
- 本地 SQLite 与本地 ArtifactStore；
- 单实例进程或团队虚拟实例运行方式；
- GraphState 的具体字段命名。

## 3. 尚未确认，不应提前固化

1. 各 Agent 的 Prompt、模型参数和完整输入输出 Schema；
2. `ContextBuilder` 的上下文协议、消息裁剪和跨轮继承规则；
3. DocWorker 的分块算法、worker 数量和汇总冲突策略；
4. TestGen 的测试格式、Oracle 类型和稳定测试集构建方法；
5. CodeAgent 的目标语言、构建命令和项目级工具链；
6. Check/Review 的 severity 定义、blocking 判据和质量评分；
7. Verification Score 的权重和 early-stop 阈值；
8. KnowledgeStore 的最终元数据 Schema；
9. 云端上传、对象存储、多人共享和跨实例调度；
10. HTTP API、鉴权、多租户、队列与运维方案；
11. DSH、其他开源 Agent 框架或远程 Agent 的具体 Adapter；
12. 真实 Codex 节点选哪个作为首个代表性集成。

## 4. 变更规则

- 新决策先更新本文件，再同步设计和测试；
- 任何节点删除、合并、绕过或职责迁移都必须显式确认；
- 暂定项必须有配置接缝，不能散落为难以替换的硬编码；
- Agent 内部实现变化不得要求重写 LangGraph 顶层图；
- 新增框架能力时，必须同时补充可自动验证的验收场景。
