# 知识回写与治理

> 本文保留旧知识治理文档中仍适用于当前框架的规则。具体评分公式和阈值尚未定案。

## 1. 增量修订

ReviewAgent 根据 EvalRunner 的失败证据定位受影响的 `knowledge_path`。DocGenAgent 优先修订相关知识，不把直接修改 CodeAgent 产物当成治本方案；同时检查关联段落的一致性，避免局部修订破坏其他定义或引用。

## 2. 知识版本

KnowledgeStore 不是单纯存放 Markdown 的目录。每一轮至少要关联：

- current version；
- historical best version；
- candidate / verified / low-confidence 等状态；
- source provenance；
- 对应的 Eval、Check、Review 报告；
- 版本父子关系、ArtifactRef 和 SHA-256。

V1 可以使用本地文件和元数据实现，接口应允许后续迁移到数据库或对象存储。

## 3. Verification Score

禁止让 LLM 自己给知识置信度打分，也不能简单使用 `confidence = test pass rate`。未来的 Verification Score 可以组合：

- critical behavior gate；
- test pass rate；
- coverage / mutation score（可获得时）；
- provenance 完整度；
- CheckAgent 的严重问题；
- ReviewAgent 的 blocking issue；
- 跨轮稳定性。

具体权重和阈值必须通过真实数据校准。Critical Gate 失败时，不得仅凭整体 pass rate 标记 verified。

## 4. 迭代、Early Stop 与 Rollback

- `maxIterations` V1 默认 5，可配置；
- 始终保留 historical best；
- 确定性 Evaluator 报告 `criticalRegression` 且存在 historical best 时，Gate 执行 rollback；
- 连续无显著改善时可 early stop，但“显著改善”和“连续轮数”的阈值待实测；
- 不在框架代码中写入未经验证的 5%、2% 等经验数字。

## 5. Review 与发布

所有结构有效的 Eval 业务报告都要经过 ReviewAgent。即使 Eval pass，Review 仍要检查证据完整性、warning、Check 发现和未覆盖高风险。

发布必须经过确定性 Gate。Review 可以降级 pass，但不能升级 fail。基础设施错误没有有效业务报告，直接失败，不发布、不进行伪归因。

## 6. 未达标后的人工治理

达到最大迭代次数仍未达标时，标记 `LOW_CONFIDENCE`，并保留可供人工治理的材料：

- failed cases 与 expected/actual；
- regression cases；
- Review 的 weak spots、knowledge path 和 corrections；
- historical best；
- knowledge diff；
- source provenance；
- 未解决风险。

人工修订不能直接标记 verified，仍需重新执行：

```text
Knowledge -> CodeAgent fresh generation -> EvalRunner -> ReviewAgent -> Gate
```

## 7. 稳定测试集

跨轮比较应尽量使用稳定的 Core Gate Test Set。新增测试先进入 Candidate/Expanded Test Set，避免每轮测试集变化导致 pass rate 不可直接比较。候选测试只有通过真实源码 Oracle 校验后，才可以进入门禁输入。
